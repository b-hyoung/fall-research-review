Week 1 안에 들어갈 알고리즘 / 포맷

디테일 · 1주차

ESP32 / Pi
JSON 메시지 포맷
공통 envelope. payload 안만 노드별로 자유.
{ "node": "tof", // "tof" | "mmwave" "ts": 1717200000123, // ms (Pi 기준 보정) "payload": { ... } }
시간 동기화: ESP32 부팅 시 SNTP 1회 → 이후 millis() + 오프셋.
mmWave
TLV 패킷 검출
TI mmWave SDK OOB Demo가 보내는 UART 패킷:
Magic Word: 02 01 04 03 06 05 08 07 Header: version, totalPacketLen, ... TLVs: type, length, payload (반복)
1주차는 매직워드 동기화까지만. 파싱은 2주차로.
ToF
4×4 zone moving average
zone 16개 각각에 5-tap 이동평균.
for each zone z: avg[z] = mean(last 5 samples of z) distance_overall = median(avg[0..15])
median으로 이상치 zone에 흔들리지 않게.
💡 1주차 규칙: 알고리즘 깊이 들어가지 않는다. 데이터가 흘러간다는 사실을 보이는 게 전부.

박형석 · ESP32+Pi
통신 안정화 + 기록
  • WiFi 끊김 시 자동 재접속
  • 패킷 손실 대응 (RAM 큐 5개)
  • Pi에서 들어오는 데이터 CSV 자동 저장
  • (나중에 튜닝 데이터로 사용)
  • 간단 웹 대시보드 띄우기 (Flask 또는 FastAPI)
유현기 · mmWave
보행 속도 + 좌우 흔들림
  • TLV 본격 파싱 (point cloud / tracker)
  • 사람 1명 추적 (가장 가까운 클러스터)
  • 속도 = √(vx² + vy²) 1초 평균
  • 흔들림 = x 좌표의 1초 표준편차
  • ESP32 #2 → MQTT 전송
조우진 · ToF
침상 상태 FSM 완성
  • 거리 임계값으로 3상태 판정
  • 채터링 방지: 0.5초 디바운스
  • 이상치: Hampel filter 추가
  • 이탈 트리거 발사 (JSON event)
  • ESP32 #1 → MQTT 전송

Week 2 안에 들어갈 알고리즘

디테일 · 2주차

ToF
상태 머신 (FSM)
if dist < 40 cm → 누움 elif dist < 100 cm → 앉음 elif dist ≥ 100 cm for 1.0s 이상 → 이탈 (트리거!)
상태 전이 0.5초 디바운스로 채터링 차단.
// Hampel filter (window=7, k=3) med = median(window) mad = median(|x - med|) if |x[i] - med| > k·1.4826·mad → x[i] = med
mmWave
보행 특징 추출
TI SDK가 주는 tracker: id, x, y, vx, vy
// 가장 가까운 사람 1명만 target = argmin_id sqrt(x² + y²) // 1초 윈도우 (50ms × 20) speed = mean(√(vx² + vy²)) sway = std(x) heading = atan2(mean(vy), mean(vx))
파싱 실패 패킷은 무시 (drop count만 로그).
ESP32 / Pi
CSV 자동 저장
Pi 5에서 MQTT 구독 → ~/data/YYYY-MM-DD.csv로 append.
ts, node, key, value 1717200000123, tof, state, sitting 1717200000150, tof, distance, 87.4 1717200000200, mmwave, speed, 1.12 1717200000200, mmwave, sway, 0.18
flat key-value로 저장 → pandas 분석 편함.
Week 3 2026. 06. 15 (월) — 06. 21 (일)

합쳐서 위험도 한 글자로

이번 주 끝나면: 화면에 "지금 위험도: 주의" 같은 한 줄이 뜬다. ToF가 "이탈" 찍히면 1초 뒤 mmWave 보행 데이터를 같이 보고 종합 판단.
박형석 · ESP32+Pi
위험도 계산기 + 4단계 분류
  • 위험도 계산 모듈 (Pi 5, Python)
  • 가중합으로 단순 시작
  • 4단계 분류 정상/주의/경고/위험
  • 대시보드에 큰 글씨 표시
  • 이력 로그 (SQLite 또는 CSV)
유현기 · mmWave
z-score 베이스라인
  • 최근 30회 보행 측정값 저장
  • SQLite에 user별 mean/std 누적
  • 현재값 → z = (x − mean) / std
  • 2σ 이상 이탈 시 위험도↑
  • 30회 미만은 고정 임계값 폴백
조우진 · ToF
이탈 임박 단계 추가
  • 8×8 zone 무게중심(centroid) 계산
  • centroid가 침대 가장자리로 이동
  • 가장자리 zone 거리 변화율 (dD/dt)
  • 임계 초과 시 "이탈 임박" 발사
  • FSM 4상태로 확장
🚩마일스톤 (6/19 금) · 일부러 침대에서 일어나면 화면이 "주의 → 경고"로 단계가 바뀐다
Week 3 안에 들어갈 알고리즘

디테일 · 3주차

Pi 5 계산
위험도 가중합 + 분류
트리거 없으면 무조건 정상.
trigger = (tof_state in ["이탈","이탈임박"]) if not trigger: return "정상" mm_risk = normalize(mmwave_features) score = 0.7·mm_risk + 0.3·tof_confidence if score < 0.3 → "주의" elif score < 0.6 → "경고" else → "위험"
가중치는 4주차에 튜닝.
mmWave
z-score 정규화
개인별 베이스라인 SQLite.
// users 테이블 CREATE TABLE gait_baseline ( user_id TEXT, feature TEXT, // "speed", "sway" values BLOB // 최근 30개 (ring buffer) ); z = (x_today - mean) / std mm_risk = sigmoid( -z_speed + z_sway )
속도↓, 흔들림↑ 일수록 위험.
ToF
centroid 추적
8×8 zone에 각각 거리/유효 마스크.
// 무게중심 cx = Σ(x_i · w_i) / Σ w_i cy = Σ(y_i · w_i) / Σ w_i w_i = 1 if zone 유효, else 0 // 가장자리 zone 변화율 edge_dD = (D_edge[t] - D_edge[t-3]) / 0.3s if edge_dD > 30 mm/s AND cx > threshold_x → "이탈 임박"

Week 4 튜닝 절차 + 자동화

디테일 · 4주차

튜닝 절차
그리드 서치
정상 시나리오 10회 위험 시나리오 10회 → CSV 라벨링 for w1 in [0.5, 0.6, 0.7, 0.8]: for th1 in [0.2..0.4]: for th2 in [0.5..0.7]: metric = FP + 2·FN log(w1, th1, th2, metric) best = argmin(metric)
목표: FP ≤ 10%, FN ≤ 5%
자동 부팅
systemd 한 줄 기동
Pi 5 부팅 시 자동 실행:
[Unit] Description=MajuBom Fall Predictor After=network.target mosquitto.service [Service] Type=simple WorkingDirectory=/home/pi/majubom ExecStart=/usr/bin/python3 main.py Restart=on-failure User=pi [Install] WantedBy=multi-user.target
ESP32는 USB 전원만 들어오면 자동.
시연 시나리오
테스트 케이스
[정상] - 정상 보행 (1.2 m/s, 흔들림 0.1) - 침대 이탈 후 안정 보행 [주의] - 천천히 일어남 - 살짝 흔들리는 보행 (0.25) [경고] - 비틀거리는 보행 (sway 0.4) - 평소보다 30% 느림 [위험] - 침대 가장자리로 쏠림 - 보행 중 정지/회복
